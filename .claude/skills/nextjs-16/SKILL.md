## What changed in Next.js 16

- **Turbopack is the default** bundler for `next dev` and `next build` (opt out with `--webpack`).
- **Request APIs are async only**: `await params`, `await searchParams`, `await cookies()`, `await headers()`, `await draftMode()`.
- **`middleware.ts` → `proxy.ts`** (deprecated filename, Node.js runtime).
- **Caching is opt-in** via `cacheComponents` + `partialPrefetching`. Nothing is cached implicitly.
- **`revalidateTag(tag)` needs a profile**: `revalidateTag(tag, "max")`. New `updateTag()` and `refresh()`.
- **`next lint` was removed**; run ESLint/Biome/oxlint directly (this repo uses `oxlint`).
- Requires Node 20.9+ and TypeScript 5.1+. Parallel route slots now require an explicit `default.js`.

## Project Config

```ts
// next.config.ts
import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  cacheComponents: true,
  partialPrefetching: true,
  turbopack: {}, // top-level, no longer experimental.turbopack
};

export default nextConfig;
```

Removed flags: `experimental.ppr`, `experimental.dynamicIO`, `experimental.useCache`, route-level `experimental_ppr` — all replaced by `cacheComponents`.

## App Router File Conventions

```
app/
├── layout.tsx          # Root layout (required)
├── page.tsx            # Home page (/)
├── loading.tsx         # Loading UI (Suspense)
├── error.tsx           # Error boundary ("use client")
├── global-error.tsx    # Root error boundary
├── not-found.tsx       # 404 page
├── (auth)/             # Route group (no URL impact)
│   ├── login/page.tsx  # /login
│   └── signup/page.tsx # /signup
├── @modal/             # Parallel route slot (needs default.tsx)
│   └── default.tsx
├── api/
│   └── route.ts        # Route handler
└── _components/        # Private folder (not routed)
```

`proxy.ts` lives at the project root (or inside `src/`), next to `app/`.

## Async Route Props

```tsx
// app/blog/[slug]/page.tsx
export default async function Page(props: PageProps<"/blog/[slug]">) {
  const { slug } = await props.params;
  const { q } = await props.searchParams;
  return <Post slug={slug} query={q} />;
}
```

`PageProps<"/route">` and `LayoutProps<"/route">` are global helpers generated by `next dev`, `next build`, or `next typegen` — no import needed. In Client Components use `use(params)` instead of `await`.

Prefer awaiting `params` **below a Suspense boundary** so the shell can stream:

```tsx
export default function Page({ params }: PageProps<"/blog/[slug]">) {
  return (
    <Suspense fallback={<Skeleton />}>
      <Post params={params} />
    </Suspense>
  );
}

async function Post({ params }: { params: Promise<{ slug: string }> }) {
  const { slug } = await params;
  const post = await getPost(slug);
  return <article>{post.title}</article>;
}
```

## Server Components (Default)

```tsx
// No directive needed - server by default
export default async function Page() {
  const data = await db.query();
  return <Component data={data} />;
}
```

Add `"use client"` only to files that need state, effects, or browser APIs. Import `server-only` in modules that must never reach the client.

## Cache Components: `use cache`

`cacheComponents: true` makes everything dynamic by default. Cache explicitly:

```tsx
// lib/posts.ts
import { cacheLife, cacheTag } from "next/cache";

export async function getPosts() {
  "use cache";
  cacheLife("hours");
  cacheTag("posts");
  return db.posts.findMany();
}
```

```tsx
// Component-level, inside a Suspense boundary
async function Projects({ userId }: { userId: string }) {
  "use cache";
  cacheLife("hours");

  const projects = await db.projects.findMany({ where: { userId } });
  return <ProjectList items={projects} />;
}
```

Rules that matter:

- Cached functions/components **must be async**; args and return values must be serializable. Unsupported: class instances, functions (except pass-through), symbols, WeakMap/WeakSet, `URL`.
- **Never** call `cookies()`, `headers()`, or read `searchParams` inside `use cache`. Read them outside and pass values as arguments.
- **Always set an explicit `cacheLife`.** Omitting it applies the implicit `default` profile, and nesting a short-lived cache inside it fails the build.
- Profiles: `seconds`, `minutes`, `hours`, `days`, `weeks`, `max` (plus custom profiles in `next.config.ts`).
- Short lifetimes (`revalidate: 0`, `expire` < 5 min, `stale` < 30 s) create dynamic holes — always wrap them in `<Suspense>`.
- `use cache: remote` uses a platform cache handler (persists across instances and deploys). `use cache: private` is a last resort for runtime data that cannot be passed in.
- With `cacheComponents`, Next.js renders routes with React `<Activity>`, so hidden routes keep state. Clean up timers/effects and close dialogs on hide.

## Revalidation

```tsx
"use server";

import { updateTag } from "next/cache";
import { revalidatePath } from "next/cache";
import { redirect } from "next/navigation";

export async function createPost(formData: FormData) {
  const title = String(formData.get("title"));
  const post = await db.posts.create({ data: { title } });

  updateTag("posts");          // read-your-writes: next read waits for fresh data
  updateTag(`post-${post.id}`);
  redirect(`/posts/${post.id}`);
}
```

| API | Where | Behavior |
| --- | --- | --- |
| `updateTag(tag)` | Server Actions only | Expires immediately, next read is fresh (read-your-writes) |
| `revalidateTag(tag, "max")` | Actions + Route Handlers | Stale-while-revalidate; use `{ expire: 0 }` to block |
| `revalidatePath(path)` | Actions + Route Handlers | Invalidates a specific route |
| `refresh()` | Server Actions only | Re-renders uncached data, leaves caches alone |

`revalidateTag("tag")` with one argument is deprecated and behaves like `{ expire: 0 }`.

## Server Actions

```tsx
// app/actions.ts
"use server";

import { z } from "zod";

const schema = z.object({ name: z.string().min(1) });

export type FormState = { error?: string };

export async function createUser(_prev: FormState, formData: FormData): Promise<FormState> {
  const parsed = schema.safeParse({ name: formData.get("name") });
  if (!parsed.success) return { error: "Invalid name" };

  const session = await auth(); // authorize inside the action, not only in proxy
  if (!session) return { error: "Unauthorized" };

  try {
    await db.users.create({ data: parsed.data });
  } catch {
    return { error: "Could not create user" };
  }

  revalidatePath("/users");
  redirect("/users"); // call outside try/catch
}
```

```tsx
"use client";

import { useActionState } from "react";
import { createUser, type FormState } from "./actions";

const initialState: FormState = {};

export function CreateUserForm() {
  const [state, formAction, pending] = useActionState(createUser, initialState);
  return (
    <form action={formAction}>
      <input name="name" required />
      <button disabled={pending}>Create</button>
      {state.error && <p>{state.error}</p>}
    </form>
  );
}
```

- Validate and authorize **inside every action** — a proxy matcher change can silently skip coverage.
- Return serializable state; don't throw for expected validation failures.
- Actions are POST requests to the current route, dispatched sequentially.

## Data Fetching

```tsx
// Parallel fetching
async function Page() {
  const [users, posts] = await Promise.all([getUsers(), getPosts()]);
  return <Dashboard users={users} posts={posts} />;
}

// Streaming
<Suspense fallback={<Loading />}>
  <SlowComponent />
</Suspense>
```

- `fetch()` is **not cached by default**; opt in with `use cache` (or `fetch(url, { next: { tags } })` for tagged responses).
- Use `connection()` when work must wait for a real request (never prerendered).
- Avoid waterfalls: start promises early, await late, and cache independent reads separately.

## Route Handlers

```ts
// app/api/users/route.ts
import type { NextRequest } from "next/server";

export async function GET(_request: NextRequest) {
  const users = await db.users.findMany({ orderBy: { name: "asc" } });
  return Response.json(users);
}

export async function POST(request: NextRequest) {
  const body = await request.json();
  const user = await db.users.create({ data: body });
  return Response.json(user, { status: 201 });
}
```

Route handlers are dynamic by default. Use `revalidateTag(tag, "max")` here — `updateTag` and `refresh` only work in Server Actions.

## Proxy (formerly Middleware)

```ts
// src/proxy.ts
import { NextResponse } from "next/server";
import type { NextRequest } from "next/server";

export function proxy(request: NextRequest) {
  if (!request.cookies.has("session") && request.nextUrl.pathname.startsWith("/dashboard")) {
    return NextResponse.redirect(new URL("/login", request.url));
  }
  return NextResponse.next();
}

export const config = {
  matcher: ["/((?!api|_next/static|_next/image|favicon.ico).*)"],
};
```

- Runs on the Node.js runtime; the `runtime` export is not available and throws.
- No matcher means it runs on **every** request, including static assets — always scope it.
- Fetch cache options have no effect inside proxy.
- Use it for optimistic redirects/rewrites/headers, not as your authorization layer.

## Metadata

```tsx
import type { Metadata } from "next";

export const metadata: Metadata = {
  title: "My App",
  description: "Description",
};

// Dynamic
export async function generateMetadata(props: PageProps<"/products/[id]">): Promise<Metadata> {
  const { id } = await props.params;
  const product = await getProduct(id);
  return { title: product.name };
}
```

Metadata reads of `params`/`searchParams` count as request-time work — `ensureStatic = "navigation"` also constrains `generateMetadata`.

## Navigation Stages and Prefetching (16.3+)

With `partialPrefetching`, a default `<Link>` loads a static **App Shell**; `<Link prefetch>` loads URL-specific content too; navigation renders the rest.

```tsx
import { navigation, prefetch } from "next/cache";

async function Comments({ id }: { id: string }) {
  await navigation(); // keep out of shell + prefetch; render on navigation
  const items = await getComments(id);
  return <CommentList items={items} />;
}

async function Sidebar() {
  await prefetch(); // keep out of the shell, but include in <Link prefetch>
  return <SidebarContent />;
}
```

```tsx
// Fail the build if dynamic content sneaks into a static route
export const ensureStatic = "navigation"; // "auto" | "shell" | "prefetch" | "navigation" | false
```

- `navigation()` / `prefetch()` must be inside a `<Suspense>` boundary and cannot be called inside `use cache`.
- `ensureStatic` works on pages and layouts; a child can be stricter, never weaker.
- `export const instant = false` disables Instant Navigation validation for a route (does not relax `ensureStatic = "navigation"`).

## Images

`next/image` defaults changed in 16:

- `qualities` defaults to `[75]`; non-matching `quality` values are coerced.
- `minimumCacheTTL` defaults to 4 hours; `maximumRedirects` to 3.
- Local `src` with query strings requires `images.localPatterns`.
- `images.domains` is deprecated — use `images.remotePatterns`. `next/legacy/image` is deprecated.

## Migrating from Next.js 15

1. `npx @next/codemod@canary upgrade latest`, then `npx @next/codemod@canary middleware-to-proxy .`.
2. `await` every `params`, `searchParams`, `cookies()`, `headers()`, `draftMode()`.
3. Rename `unstable_cacheLife`/`unstable_cacheTag` → `cacheLife`/`cacheTag`.
4. Remove `experimental.ppr`, `experimental.dynamicIO`, `export const experimental_ppr`, and every `runtime` export under Cache Components.
5. Add a second argument to `revalidateTag` (`"max"` for SWR, or switch to `updateTag`).
6. Add `default.js`/`default.tsx` to every parallel route slot.
7. Replace `next lint` with a standalone linter.
8. Add `data-scroll-behavior="smooth"` to `<html>` if you relied on automatic smooth scrolling.
